## 生成直後の保存データ

28 bytes の出力を取得した。初期オブジェクトは空データではなく、時刻0・120 BPMに対応するデータを保存する。

```text
74 65 74 72 14 00 00 00 10 00 00 00 00 00 00 00
00 00 00 00 00 00 00 00 00 00 5e 40
```

先頭は `tetr`、チャンクのデータ長は20、続くレコードサイズ値は16。レコード先頭は32ビット符号付き時刻、次の4 bytes は保存時に0になる領域、末尾8 bytes は little-endian の double テンポ値。静的な Save のゼロ初期化と SDK の16 bytes 配置にも対応する。通常の複数イベントは同じレコードを並べる。全イベント削除後はデータ長4・レコードサイズ16の12 bytes チャンクになる。

Load はチャンク識別子 `0x72746574` と比較し、サイズ値とレコードを読み取る（RVA `0x7318` 以降）。各レコードを内部オブジェクトへ移し、読込後に `0x6670` の処理を呼ぶ。

## 読込失敗から分かった事前条件

プローブで保存データを同じオブジェクトへ Load すると終了コード `0xC0000005` になった。例外の命令 RVA は `0x66af`、アクセス先は0。これは元 DLL を変更していない状態の結果。

静的には `0x66ac` が `CTempoMgr + 0x34` を読み、`0x66af` でそのポインターを逆参照する。さらに仮想関数テーブルの `+0x4c` を呼び出してストリームを得ようとする。`+0x34` はプロパティ設定処理の値2で Framework IID を取得して保存する場所であり、今回のプローブでは未設定だった。

同じ処理は後段で `CTempoMgr + 0x50` のオブジェクトにもアクセスする。そこはプロパティ値1から IID `{F96029A1-4282-11D2-8717-00600893B1BD}` を要求して設定する。SDK 宣言と照合した結果、IDirectMusicTrack である。後続試験でランタイムのテンポが更新されることも確認した。

したがって保存形式だけを実装しても接続仕様は完成しない。失敗を避けるために原版をパッチしたり、必要な呼び出しを無条件に省略した結果を互換性の証拠にしたりはしない。

## 接続済みホストでの確認

`work/reference/tempo/20261002T003412534Z/` では、プロパティ2に限定 Framework、プロパティ1に実際の COM テンポトラックを設定した。Framework は値2と保存形式 GUID を受け取り、PersistInfo を備えるメモリストリームを生成する。Load と再保存が成功し、初期の28 bytes と一致した。

## イベント順序とテンポ取得

Load は既存イベントを除去し、`0x65c4` の挿入処理に置換フラグ false で渡す。通常ケースの観測結果は次のとおり。

- 順不同の入力は時刻昇順で保存される。
- 同時刻の2イベントは入力順のまま両方保存される。時刻768に150と95を入れた場合、768と769の取得値は95。
- StripMgr の GetParam（スロット4、`0x7191`）は選ばれたイベントの絶対時刻を返す。時刻769での取得例は時刻768、次イベントまで767。
- ランタイムの GetParam は同じ例で時刻-1を返す。この環境でのランタイムの時刻値は問い合わせ位置からの相対値なので、編集側と同一の時刻契約にしない。
- イベントがない場合、編集側は `S_FALSE` と120 BPMを返す。最後のイベント以後の next は0。

静的な検索処理 `0x6ed9` と Save は、double 0（RVA `0x1c88`）との x87 比較と `test ah, 0x44` のパリティ分岐を使う。通常の「正の値だけ」という範囲検査とは断定しない。負値・0・NaN・無限大を実際に読ませたときの保存・ランタイム連携は未検証。レコードサイズは Load 内部で最大16へ制限されるが、拡張レコードの余剰を正しく飛ばすかは別問題であり、一般化していない。

## 小節・拍・tick と位置変更

原版 TempoStripMgr の SHA-256 は冒頭と同じ `bb9811c74f68dcf0b37d32fe2ae89d3e45962e59b95f1ec93ddf7a12635a5c95`。下記 RVA はこの DLL 内を指す。

GetData が返す既知の先頭0x22 bytesは次の配置。全体の割当サイズや未使用領域の意味まで確定したものではない。

| オフセット | 型 | 観測・静的解析で確認した内容 |
| --- | --- | --- |
| 0 | LONG | イベントの絶対時刻 |
| 8 | double | テンポ |
| 16 / 20 / 24 | LONG × 3 | 0始まりの小節・拍・tick |
| 28 | DWORD | 今回の単一選択では0、意味は未確定 |
| 32 | WORD | 単一選択では0。複数選択では値2を原版・代替版で確認 |

時刻から位置への変換は `0x58d3`。負の時刻は小節0・拍0・tick=時刻、それ以外は Timeline の ClocksToMeasureBeat（スロット13）で小節・拍を得て、MeasureBeatToClocks（15）の結果を元時刻から引いて tick とする。位置から時刻へ戻す `0x594c` はスロット15の結果に tick を加え、負になる結果は0へ制限する。

SetData（`0x79a5`）は最初の選択イベントを対象にする。小節・拍・tickが変わらない場合はテンポを変更する。位置が異なる場合の分岐 `0x7ac7` は、位置変換後に曲の長さ（Timeline のプロパティ1）を取得し、長さの位置に対応する小節番号から1を引いた値を最終小節とする。移動先の小節がそれを超えた場合、時刻を長さ−1へ設定する。単純な時刻の上限判定と同じとは限らない。

時刻が変わった場合、`0x7b3e` 以降で既存ノードを取り除き、`0x65c4` へ置換フラグ falseで挿入し直す。小節変更の分岐では、同時に渡したテンポ変更値を代入する経路を通らない。末尾制限、同時指定の優先順位、複数選択、同時刻への移動は後続の `20261002T020601617Z` で動的にも確認し、代替版と一致した。

4/4拍子、長さ30720、単一イベントの時刻768/900/4708でのテンポ変更と1小節移動は、原版実行 `20261002T014530015Z` と代替実行 `20261002T015126510Z` で一致した。その後、境界・複数選択と拍子変更を加え、代替実装も位置をイベント内に保持する構造へ改めた。Load と位置更新通知でキャッシュを更新し、拍子変更通知では保持した位置から時刻を更新する。

位置変換のために追加した原版 TimeSigStripMgr は CLSID `{8C6005D2-ABDA-11D2-B0D9-00105A26620B}`、SHA-256 `898258cfbf1b17bef0054695d25331c530e2ee2846c5d45073a8fd5670484bb7`。同 DLL の Load `0x7cc6` → 読取 `0x7884` は `tims` と8 bytesレコードを受け付ける。試験入力は時刻0・4/4・grids=4の自作データ20 bytes。生成直後の空状態と、入力後の位置変換成功を別々に観測した。ランタイムが未接続なら同期処理 `0x6ac1` は失敗を返すが、Load はそれを伝播しない。拍子のランタイム同期を確認した結果ではない。

## strip 実装に向けた追加調査

CTempoStrip の QueryInterface（`0x873e`）は次の IID を持つ。IUnknown と Strip は先頭位置を共有し、StripMgr とは別の COM 同一性を持つ。コンストラクター `0x8688` は管理オブジェクトを `+0x28` / `+0x2c` に保存するが、その経路で管理オブジェクトの AddRef は呼んでいない。単純な相互強参照に置き換えると循環参照になり得るため、実装では所有権を明示する必要がある。

| 接続 | IID | 位置 |
| --- | --- | --- |
| Strip | `893EE17A-04A3-11D3-894C-00C04FBF8D15`（GUID RVA `0x2654`） | `+0` |
| StripFunctionBar | `86D596CC-B302-11D1-888F-00C04FBF8D15`（`0x2644`） | `+4` |
| TimelineEdit | `8640F4B2-2B01-11D2-88F9-00C04FBF8D15`（`0x25e4`） | `+8` |

Strip の GetStripProperty（スロット4、`0x8884`）の静的分岐：0は BSTR の表示名、1は VT_BOOL 値1、6/8/9は VT_INT 値20、7/10は VT_BOOL 値0、12は VT_UNKNOWN の管理オブジェクト。0/1/6/7/8/9/10/12は `20261002T013332800Z` までに動的に照合した。未対応番号は `E_FAIL`、出力 null は `E_POINTER` という静的分岐がある。BOOL の true が通常の VARIANT_TRUE (-1) ではなく1である点も保持する。

Strip の Draw は `0x9bcb` → `0xa516` の `ret 0x10`、OnWMMessage は `0xaeee` → `0xb27e` の `ret 0x18`。これは x86 の引数幅の根拠であり、描画内容や引数の意味すべての確定を意味しない。

TimelineEdit の Cut / Copy / Paste は各1引数、Insert / Delete / SelectAll と CanCut / CanCopy / CanInsert / CanDelete / CanSelectAll は引数なし、CanPaste は1引数という呼出し幅を確認した。Cut / Copy / Paste / CanPaste に渡すデータオブジェクトの完全な契約は未復元。後続の試験では SelectAll と Delete に加え、Insert と非nullのデータオブジェクトを使うCut / Copy / Pasteも動的に比較した。

Timeline の通知登録内部（同 DLL `0x105d6`）は対象ポインターと groups を格納し、通常経路では対象への AddRef を行わない。登録解除 `0x106fd` は対象ポインター・GUID・groups が一致する登録を外し、見つからない場合 `E_INVALIDARG`（`0x107f8`）を返す。アンロード成功だけでは登録解除漏れを十分に検出できないため、存在・重複なし・切断後不在を明示的に調べる試験を追加した。追加ビルドは一度起動拒否されたが、後続の同一ハッシュの試行で成功。原版 `20261002T021855247Z` と代替版 `20261002T021919993Z` で6 GUIDの登録・解除状態が一致した。2種類の通知が実際に代替版へ届き、処理結果が一致することも検証済み。後続でテンポ変更通知の通常編集経路を追加した。残る3種類と再生中の分岐は別途確認が必要である。

## 貼付けの位置補正と統合

Paste（RVA 0xa7f2）は CanPaste が S_OK でなければ E_UNEXPECTED。非 null のデータオブジェクトを渡す経路では、Timeline の44で貼付けモード、6で時刻カーソルを取得し、13/15で拍頭へ合わせる。モード1は上書きで、データ境界の長さを使って「丸める前のカーソル～カーソル＋境界長」を両端込みで削除する（削除ヘルパー0x6b79）。

貼付け本体0xa519は24バイトの tetr を読み、最小・最大の相対時刻と最初の最小イベントのtickを調べる。基準位置＋最大時刻が曲の長さ以上なら「長さ−最大時刻−1」を拍頭に丸め直す。その後も最小時刻が負になるなら「最小イベントのtick−最小相対時刻」を基準にする。二つの補正を順に適用するため、短い曲では最後のイベントが長さを超える場合がある。

各イベントは位置を計算して選択状態にする。挿入ヘルパー0x65c4の置換モードは同一絶対時刻の最初のイベントだけを置換し、後続の同時刻イベントは保持する。変更時のUndo用リソースIDは103で、文字列は Paste Tempo(s)。ランタイム同期、変更通知、再描画、プロパティ表示要求が続く。コピーのpadding +4..7 / +20..23はこの読込でも参照しない。

原版20261002T030521345Zと代替版20261002T030704686Zで7ケースが一致した。非0カーソルの試験には原版 Timeline 内の TimeStripMgr を接続する。GetInternalClipFormat は元データの利用可能状態を消費するため、試験入力の事前観測には別のデータオブジェクトを使う。通常の正の有限テンポについて実装・比較済みだが、0テンポのプレースホルダー、破損データ時の部分更新、プロパティ表示とシステムクリップボード経路は未対応。

## カーソル位置でのテンポ変更

OnUpdate の0x786eは通知データnullをE_POINTERとし、+8のdoubleを0x74ecへ渡す。0x74ecはTimelineのカーソル0を取得し、その時刻以前で最後の0以外のテンポイベントを選ぶ。対象なし・同一テンポなら変更しない。選択フラグと位置を保持したままテンポを更新し、操作名111（Change Tempo）、再描画、同期・変更通知へ進む。Timelineプロパティ12が非0なら、同期の間だけ0にして最後に1へ戻す。

代替版は通常の正の有限テンポでこの編集経路を実装した。直接OnUpdateとTimeline配送、空・先頭より前・同時刻・変更なしを含む8ケースが一致した。原版0x7576～0x75d6の再生状態がある場合の64バイトメッセージ生成・送信と、0x7601以降のページ更新は未実装。通知ハンドラー全体の互換性とは区別する。

## 範囲選択

SetStripProperty はRVA 0x897e。プロパティ3/4はVT_I4のみを受け付け、strip +0x1c / +0x20へ範囲開始・終了を保持する。プロパティ2はboolValを符号拡張して+0x24に保持し、vtを検査しない。未知の番号または3/4の型不一致はE_FAIL。通常の選択更新では以前の選択を解除し、ガターが有効かつ開始と終了が異なる場合に0x64ebへ進む。

0x64ebは開始−1を0へ置換し、両端をTimelineスロット13で小節・拍へ変換する。各イベントに保持した小節・拍と比較し、両端の拍を含めて選択する。開始より後かつ終了より前の小節、開始小節の開始拍以降、終了小節の終了拍以前を個別に判定する。同一小節の場合は拍の両端条件を同時に満たすものを選ぶ。このため逆順の異なる小節は単純な空範囲にはならない。

通常経路を代替版へ実装し、8ケースで選択先頭、コピー対象、削除後データ・保存・再読込・同期が一致した。比較は20261002T032657289Z。strip +0x30によるドラッグ中の抑制、+0x38の選択補助状態とページ更新、Timelineからの実画面操作の配送は未解明・未対応として残る。


## 描画と直前テンポ表示

TempoStrip::Draw は strip vtable のスロット3、RVA 0x9bcb～0xa516。引数は HDC、DWORD view、LONG xOffset、戻り値は HRESULT。今回の経路では view の値を参照しない。Timeline のスロット9 DrawMusicLines(HDC,DWORD,DWORD,DWORD,LONG) へ type=1、groups=FFFFFFFF、index=0を渡す。位置変換には7・8・13・15・16、表示開始には6のマーカー3を使う。

ラベルは %.2f。通常は拍頭X+1−xOffset、上端0・下端20、DT_NOPREFIXで描く。同じ拍の複数イベントは斜体。幅は文字幅と拍幅の大きい方とし、次の異なる拍のラベル位置で切る。選択パスでは拍頭X−xOffsetから描き、矩形をInvertRectする。ガター範囲の反転は別処理で、通常の全選択とは画素が異なる。DCの元フォント・文字色を戻し、一時的な斜体フォントを削除する。

表示開始より前のテンポは、最初の完全に見える拍へ位置を丸め、直前イベントをRGB(168,168,168)で描く。ただし通常ラベルとの位置関係で抑制・クリップされる。同じ拍内の直前候補の選択は逆方向の探索（0x8a86）を使い、通常の前方探索（0x8b3e）と代表イベントが異なる場合がある。内部のアクティブフラグによる切替は、マウス操作後の比較が必要。

代替版にDrawを実装し、最初にメモリ上の12ケース・24画像を比較した。後続の原版20261002T040055150Z・代替版20261002T040059698Zでは、実ウィンドウと非0の表示開始を使う8ケースを追加し、全20ケース・40画像のBMP全バイト一致を確認した。直前の同じ拍に120・130・140 BPMがあるケースでは140.00を斜体で灰色表示する。灰色画素数の検査を加え、両実装が何も描かず一致するだけでは通らないようにした。マウス操作後の内部状態、異なるフォント、異なるDPI、本体UI上での比較は未完了。

## クリック選択と空拍

原版の WM_LBUTTONDOWN 分岐は RVA 0xb133 から0xad3a、WM_LBUTTONUP は0xb0bbへ進む。拍内の最初の実イベントを選び、通常クリックでは以前の選択を解除する。既選択の実イベントを押した場合は押下時に複数選択を保持し、解放時に単一選択へ縮める。Ctrlで未選択のイベントを追加し、Shiftではアンカーとクリックした拍を含む範囲を選ぶ。Ctrlで既選択のイベントを押した場合のOLEドラッグは未実装。

空拍には内部の0 BPMイベントを作る（0x6dd0）。Shift範囲内の空拍にもプレースホルダーを置く（0x99e0）。これを選択の描画に使うが、保存・テンポ検索・コピーから除外する。SelectAllは0以外だけを選択し、CanSelectAllも実イベントの存在で判定する。外部からの読込・貼付けで0 BPMを渡す仕様は別途未対応である。

GetData（0x6136）は選択された実イベントを返す一方、SetDataが使う探索（0x64d2）は選択されたプレースホルダーも含む。空拍からShift選択し、GetDataの結果を変更してSetDataへ渡すと、最初の空イベントの移動が優先され、実イベントのテンポは変更されないケースがある。プローブのshift_from_emptyで保存・再読込まで確認した。Insertは同じ拍のプレースホルダーを120 BPMの実イベントへ変更する（0x9082）。

マーカーを0に戻す処理（0x85a3）ではstrip +0x30を設定し、SetStripProperty（0x89d2）が再入しても選択を消さない。代替版でもこの抑制を実装した。通常のクリック13ケースは比較済みだが、外部から選択を解除した直後のShiftアンカー、代表イベントの切替、ドラッグ、本体UIからの入力配送は未検証。

## 右ドロップメニューと実OLE中止の追加観測（2026-10-02）
