# 0002：新製品と旧Windows環境を分離する

状態：採用済み。決定日：2026-11-10、ユーザー指定。基本配置への移動を同日実施。

## 判断

ルートを新製品の開発入口にする。`apps/desktop/`と4つの`modules/`を責務別に置き、旧ソース・試験・スクリプト・文書は内部配置を保って`legacy/windows/`へまとめる。

旧ツールが相対参照する作業ルートを一つに保ち、新しいMacビルドへWindows専用のRC・SDK・COM処理が入らないようにする。現行設計と採用判断は`docs/`に置き、旧資料には索引から案内する。

## 適用範囲

新コードは旧ソースを直接リンクせず、必要な機能を新しい型とAPIへ抽出する。新旧は同じGitリポジトリで管理する。空の下位ディレクトリ、仮の製品ターゲット、用途のないライブラリは増やさない。

現在の配置は[リポジトリ構成](../architecture/repository-layout.md)、背景は[採用した提案書](../proposals/repository-structure-proposal-2026-11-10.md)、実施結果は[配置変更の記録](../development/repository-layout-migration-2026-11-10.md)を参照する。
